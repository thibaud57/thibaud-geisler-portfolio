# Description

`c15t` (prononcé "consent", Apache 2.0) est une CMP (Consent Management Platform) headless conçue pour les apps modernes React/Next.js. Elle gère la persistance du consentement, le banner et la modale de préférences, la résolution de la politique applicable et la traduction multi-langues, avec 3 modes : `offline` (règles dans le bundle, choix dans le navigateur, zéro backend), `hosted` (backend c15t ou Inth) ou `manifest` (défaut Next.js, politique téléchargée au build, résolue côté serveur).

Depuis la v3, le paquet à installer est `c15t` (imports `c15t/next`, `c15t/react`, `c15t`). `@c15t/nextjs` reste publié et ses imports continuent de fonctionner, mais la doc embarquée (`node_modules/c15t/docs/`, à lire avant d'écrire du code : elle correspond à la version installée) recommande `c15t`, et `offline()` en transport (`c15t/react`) n'est pas exporté par `@c15t/nextjs`.

Dans ce projet, on utilise le mode `offline` car le portfolio est single-user, n'a pas besoin d'audit trail serveur, et la juridiction est forcée à FR pour appliquer GDPR/CNIL inconditionnellement. `ConsentProvider` est monté dans `Providers.tsx`, `ConsentBanner` et `ConsentDialog` y sont chargés par `next/dynamic`, leurs translations FR/EN proviennent de `@c15t/translations/all`, et le thème est rendu par `ConsentTheme` dans le layout serveur (le provider ne génère plus de CSS, voir section Theming).

# Concepts Clés

## ConsentProvider en mode offline

### Description

Provider racine qui initialise le store de consentement et expose le contexte React aux descendants. Le mode `offline` résout la politique dans le navigateur à partir de règles fournies par le code et stocke le choix en localStorage + cookie, sans appel réseau. Combiné à `overrides.country: 'FR'` et à la règle `europeOptIn`, il force le modèle opt-in GDPR/CNIL sans géo-détection.

### Exemple

```tsx
'use client'
import { policyRulePresets } from 'c15t'
import { ConsentBanner, ConsentDialog, ConsentProvider } from 'c15t/next'
import { offline } from 'c15t/react'
import { baseTranslations } from '@c15t/translations/all'

export function Providers({ children }: { children: React.ReactNode }) {
  return (
    <ConsentProvider
      options={{
        mode: offline({ policyRules: [policyRulePresets.europeOptIn()] }),
        overrides: { country: 'FR' },
        consentCategories: ['necessary', 'marketing'],
        legalLinks: {
          privacyPolicy: { href: '/fr/confidentialite', target: '_self' },
        },
        i18n: {
          locale: 'fr',
          detectBrowserLanguage: false,
          messages: baseTranslations,
        },
      }}
    >
      {children}
      <ConsentBanner hideBranding legalLinks={['privacyPolicy']} />
      <ConsentDialog hideBranding legalLinks={['privacyPolicy']} />
    </ConsentProvider>
  )
}
```

### Points Importants

- Le provider doit être un Client Component (`'use client'`) car il utilise React Context et accède à `localStorage`
- **`offline` existe en deux formes** : `offline` de `c15t/next` est une donnée pour `c15t.config.ts` (racine serveur `ConsentRoot`), `offline` de `c15t/react` est le transport à passer à `ConsentProvider`. Avec `ConsentProvider`, importer celui de `c15t/react`
- `ConsentRoot` + `resolveConsent()` (recommandé par la doc pour un rendu serveur) lit les cookies de la requête : incompatible avec le site public du projet, dont le shell reste statique (Cache Components, ADR-022). Le projet garde l'initialisation navigateur
- `mode`, `persistence` et `storageConfig` sont lus une seule fois au montage : remonter le provider pour les changer
- Sans `policyRules`, `offline()` applique `recommendedPolicyRules()` : opt-in pour l'Europe, no-prompt pour les autres pays connus. `europeOptIn()` explicite fige le comportement voulu
- `offline` n'a pas d'audit trail serveur, et la doc le déconseille pour la production : si un audit CNIL formel exige une preuve datée par visiteur, passer en `hosted` ou `manifest` avec un backend
- `overrides.country: 'FR'` force la juridiction sans API géo. À retirer si l'app sert plusieurs juridictions
- `consentCategories` : valeurs autorisées `'necessary' | 'measurement' | 'marketing' | 'experience' | 'functionality'`. `necessary` est toujours vrai et non modifiable
- `detectBrowserLanguage: false` désactive la lecture de `navigator.language` au montage, qui écraserait la `locale` initiale
- **Stockage** : clé `c15t` (localStorage et cookie), comme en v2. Un choix enregistré en v2 est lu par la v3 sans réécriture (constat du 27 octobre 2026). Un refus v2 reste respecté. Un accord v2 est redemandé une fois (la bannière réapparaît), cause non isolée (la doc de montée indique qu'un accord v2 est redemandé quand la politique d'un preset a changé depuis l'enregistrement) : acceptée lors de la montée en v3

## Composants UI : ConsentBanner & ConsentDialog

### Description

`ConsentBanner` est le bandeau bottom-left affiché tant que le visiteur n'a pas interagi. `ConsentDialog` est la modale de préférences granulaires (toggles par catégorie). Tous deux acceptent `hideBranding` pour masquer le badge "Secured by c15t" (gratuit, fonctionne en offline).

### Exemple

```tsx
import { ConsentBanner, ConsentDialog } from 'c15t/next'

<ConsentBanner hideBranding legalLinks={['privacyPolicy']} />
<ConsentDialog hideBranding legalLinks={['privacyPolicy']} />
```

### Points Importants

- Les 3 boutons par défaut (`Tout rejeter` / `Accepter tout` / `Personnaliser`) sont rendus au même niveau visuel : conforme à l'exigence CNIL "rejet aussi simple que l'acceptation"
- La bannière ne réapparaît pas tant qu'un choix valide est enregistré
- Pour ouvrir la modale depuis un bouton custom (footer "Gérer mes cookies"), appeler `useSetActiveUI()('dialog')`
- Les composants de la v3 rendent leur CSS en éléments `<style>` : **aucun import `styles.css`**. Le garder (avec `styles: false`) ne sert qu'avec Tailwind 3 ou une cascade layer nommée
- Le projet charge les deux composants par `next/dynamic` (`ssr: false`) depuis un module dédié (`consent-ui.tsx`) : cette frontière de chunk garde leur code et leur CSS hors du bundle synchrone
- Le titre du bandeau et de la modale est un `h2` (c'était un `div` en v2). Les boutons des accordéons héritent de la police du site (en v2, ils retombaient sur `system-ui`)
- `noStyle: true` au niveau du provider supprime tous les styles défaut (markup nu) pour une UI entièrement custom

## Synchronisation locale next-intl ↔ c15t

### Description

c15t et next-intl gèrent leurs i18n indépendamment. Pour que le banner suive FR ↔ EN quand le visiteur change de langue, il faut appeler `setLanguage(locale)` à chaque changement de `useLocale()` next-intl.

### Exemple

```tsx
'use client'
import { useSetLanguage } from 'c15t/next'
import { useLocale } from 'next-intl'
import { useEffect } from 'react'

export function ConsentLanguageSync() {
  const setLanguage = useSetLanguage()
  const locale = useLocale()

  useEffect(() => {
    setLanguage(locale)
  }, [locale, setLanguage])

  return null
}
```

À monter à l'intérieur de `<ConsentProvider>`, au-dessus des composants d'UI.

### Points Importants

- En offline, `setLanguage()` ne fait pas d'appel réseau : il pioche dans l'objet `messages` passé au provider (qui doit donc inclure les 2 locales)
- `useSetLanguage()` retourne une fonction synchrone (`(code: string) => void`), alors que `setLanguage` de `useConsentManager` (v2) retournait une promesse
- Toujours inclure `setLanguage` dans les deps du `useEffect`

## Hooks de lecture du consentement (gating de scripts tiers)

### Description

`useConsentManager()` n'existe plus en v3 : chaque champ a son hook (un composant ne se re-rend que pour le champ qu'il lit). `useConsent('<catégorie>')` retourne un booléen, `useSetActiveUI()` ouvre ou ferme la bannière et la modale, `useSetLanguage()` change la langue. La liste complète des correspondances v2 → v3 est dans `node_modules/c15t/docs/frameworks/next/upgrade-v3.md`.

### Exemple

```tsx
'use client'
import { useConsent } from 'c15t/next'

export function EmbedGate() {
  const marketingAccepted = useConsent('marketing')

  if (!marketingAccepted) {
    return <p>Acceptez les cookies marketing pour afficher le contenu.</p>
  }

  return <iframe src="https://example.com/embed" title="Embed" />
}
```

### Points Importants

- Le hook re-rend le composant à chaque changement de la catégorie lue : pattern réactif natif
- Un appel par catégorie, en tête de composant (règle des hooks)
- `useConsent` retourne `false` pour une catégorie non déclarée dans `consentCategories`
- Les hooks doivent être appelés dans un Client Component descendant du provider
- Pour éviter un blanc au rendu initial, garder un placeholder accessible derrière le gate

## Theming via ConsentTheme et slots

### Description

c15t expose des design tokens (`--c15t-primary`, `--c15t-surface`, `--c15t-text`, `--c15t-border`, `--c15t-radius-md`, `--c15t-font-family`…) que les composants consomment. **En v3, `options.theme` ne génère plus de CSS** : les tokens sont rendus par `<ConsentTheme theme={theme} />`, composant serveur à poser une fois dans le layout (il produit un `<style id="c15t-theme">`). `options.theme` du provider ne sert plus qu'aux `slots` (classes ajoutées à une partie d'un composant) et à `consentActions`.

### Exemple

```tsx
// consent-theme.ts : module partagé, sans 'use client'
import type { ConsentProviderOptions } from 'c15t/react'

const colors = {
  primary: 'var(--primary)',
  primaryHover: 'var(--primary)',
  surface: 'var(--card)',
  text: 'var(--foreground)',
  textOnPrimary: 'var(--primary-foreground)',
} as const

export const consentTheme = {
  colors,
  dark: colors,
  radius: { md: 'var(--radius)' },
  typography: { fontFamily: 'var(--font-sans)' },
  slots: {
    consentWidgetFooter: 'border-t! border-border!',
  },
} as const satisfies NonNullable<ConsentProviderOptions['theme']>
```

```tsx
// layout.tsx (Server Component)
import { ConsentTheme } from 'c15t/next'

<ConsentTheme theme={consentTheme} />

// providers.tsx (Client Component) : options={{ theme: consentTheme, ... }}
```

### Points Importants

- **`var()` supportées** : c15t passe les valeurs verbatim dans son CSS. `var(--primary)` résout au niveau du consommateur et bascule light/dark avec la classe `dark` de `<html>` posée par le store de thème (`src/lib/theme.ts`)
- **`textOnPrimary` explicite** : si omis, c15t calcule un contraste en parsant `primary` comme couleur littérale, ce que `var(--primary)` empêche (repli sur blanc)
- **`dark` explicite** : le thème généré écrit ses valeurs sombres sur `:root:root.dark`, qui battent les valeurs de `colors` si `dark` ne les redéfinit pas. Passer les mêmes références `var()` en `colors` et `dark`
- **Détection du mode sombre** : `colorScheme` non défini fait copier la classe `dark` de `<html>` : compatible avec le store de thème du projet. Ne pas forcer `colorScheme: 'system'`, la media query remplacerait la classe
- **Spécificité** : les classes de c15t 3 se doublent (`.a.a`, spécificité 0,2,0). Une classe de slot isolée perd, d'où le suffixe `!` sur les propriétés de layout (`gap-4!`, `border-t!`). Les variantes `[&_a]:` et `[&_button]:` (0,1,1) suffisent pour les enfants
- **Slots utiles** : `consentBannerFooter`, `consentWidgetFooter` (le pied de la modale, il n'y a pas de `consentDialogFooter`), `consentWidgetFooterSubGroup`, `consentBannerDescription`, `consentDialogDescription`. Liste complète : `node_modules/c15t/docs/customization/slots.md`
- **Rendu de référence** : les slots du projet ramènent le rendu de c15t 3 à celui de c15t 2 (filet au-dessus du pied de la modale, boutons du pied qui rétrécissent au lieu de déborder, liens non soulignés). Sans eux, le bouton « Enregistrer » déborde de la carte à 1280 px (relevé le 27 octobre 2026). Arbitrage consigné dans [DESIGN.md](../DESIGN.md) § Mapping Composants > Overlays
- **Overrides dans `globals.css`** : à éviter, le `<style id="c15t-theme">` généré et la spécificité doublée des composants les écrasent
- **Liste des tokens** : `node_modules/c15t/docs/customization/tokens.md`

## Translations FR/EN via @c15t/translations/all

### Description

Le package `@c15t/translations` fournit les traductions complètes de 30+ langues (dont `fr`, `en`, `de`, `es`, `it`…). L'import `/all` charge `baseTranslations: Record<string, CompleteTranslations>`, à passer au `messages` du provider. Évite de retranscrire les strings du banner et de la dialog.

### Exemple

```tsx
import { baseTranslations } from '@c15t/translations/all'

i18n: {
  locale: 'fr',
  detectBrowserLanguage: false,
  messages: baseTranslations,
}

// Override partiel d'une string : cloner, ne jamais muter l'objet de la lib
const messages = structuredClone(baseTranslations)
messages.fr.cookieBanner.description = 'Texte du bandeau'
```

### Points Importants

- `@c15t/translations` doit être installé explicitement, même s'il arrive en transitif : sinon `Module not found: Can't resolve '@c15t/translations/all'`. Le garder à la même version que `c15t`
- L'import sans `/all` ne re-exporte que `enTranslations` : pour le multi-langue il faut `@c15t/translations/all`
- Un override partiel passé en `i18n.messages` se fusionne sur les messages de la langue (partiel autorisé en v3). Un objet complet typé `CompleteTranslations` exige les clés ajoutées en v3 (`consentGate`, `rights`…)
- Les clés (`common.acceptAll`, `cookieBanner.description`…) suivent la shape `CompleteTranslations` exposée par les types

## Liens légaux dans le banner

### Description

`legalLinks` au niveau du provider fournit les liens (politique de confidentialité…) ; la prop `legalLinks` des composants choisit lesquels afficher dans la bannière et la modale.

### Exemple

```tsx
options={{
  legalLinks: {
    privacyPolicy: { href: '/fr/confidentialite', target: '_self' },
  },
}}

<ConsentBanner legalLinks={['privacyPolicy']} />
```

### Points Importants

- `target: '_self'` pour une navigation interne. `'_blank'` ouvre un nouvel onglet
- Les hrefs sont rendus tels quels : pour du multi-locale, les calculer selon la locale courante
- Pas obligatoire pour la conformité CNIL si le footer contient déjà ces liens, mais recommandé au moment du choix
- Les liens de la bannière ne sont pas soulignés dans le projet (slot `[&_a]:no-underline`), le style des slots est dans `consent-theme.ts`

# Bonnes Pratiques

## ✅ Recommandations

- **Mode offline pour ce projet** : single-user, pas d'audit trail serveur requis, zéro coût opérationnel, aucune dépendance SaaS
- **`overrides.country: 'FR'` + `europeOptIn()`** pour forcer GDPR/CNIL inconditionnellement
- **`hideBranding` sur Banner et Dialog** : retire "Secured by c15t", look 100 % projet
- **Thème par `ConsentTheme` (layout serveur) et `consent-theme.ts` partagé** avec des références `var()` vers les tokens shadcn/Tailwind 4 du projet
- **Sync next-intl ↔ c15t via `<ConsentLanguageSync />`** : composant minimaliste, à monter au-dessus des composants d'UI
- **Installer `@c15t/translations` explicitement**, à la même version que `c15t`
- **Gating des scripts tiers via `useConsent('marketing')`** plutôt que d'injecter le script global et le retirer après un refus
- **Prouver un changement de rendu sur une capture** (bannière et modale, FR et EN, clair et sombre, desktop et 320 px), pas en relisant les classes : c'est ce qui a révélé le débordement du pied de la modale lors de la montée en v3

## ❌ Anti-Patterns

- Monter `ConsentProvider` dans un Server Component : c'est obligatoirement un Client Component
- Importer `offline` depuis `c15t/next` pour le passer à `ConsentProvider` : c'est la forme donnée pour `c15t.config.ts`, pas un transport
- Utiliser `ConsentRoot` + `resolveConsent()` sur le site public : le shell statique (Cache Components) ne lit pas les cookies de la requête
- Utiliser `useConsentManager` ou `ConsentManagerProvider` (v2) : exports supprimés en v3
- Appeler `setLanguage` depuis next-intl directement : les deux i18n sont indépendants, c15t n'écoute pas next-intl
- Embarquer le mode `hosted` "au cas où" : un backend et une dépendance réseau pour aucun bénéfice tant qu'aucun audit trail n'est exigé
- Importer `c15t/next/styles.css` sans `styles: false` : les règles seraient livrées deux fois, et la feuille retarde le premier rendu
- Surcharger les tokens c15t dans `globals.css` : écrasés par le `<style id="c15t-theme">` et par la spécificité doublée des composants
- Poser une classe de slot de layout sans `!` : elle perd contre la classe doublée de c15t
- Utiliser `noStyle: true` en essayant d'override des variables CSS en parallèle : `noStyle` retire tout, les variables n'ont plus rien à styler
- Ajouter une catégorie `analytics` "pour préparer Umami" : Umami est cookie-less par design (ADR-007), YAGNI
